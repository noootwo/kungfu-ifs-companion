# APP 架构笔记

只有用户明确要求设计或实现陪伴类 APP、后端、提示词栈、评测系统或 agent 系统时使用。

## 分开 Skill 与 APP runtime

轻量 Skill 负责陪伴行为。生产级 APP 还需要确定性、安全、持久化和可观测性等机制。普通 Skill 使用不要把这些 APP 运行时问题全部带进来。

## 可复用的生产概念

- 单一可见的陪伴者身份通常比多个独立 agent 更容易建立信任。
- 把内在部分当作结构化的用户状态对象，而不是独立自治 agent。
- 路由决策保持小而清楚：谁回答、是否需要记忆、是否需要安全稳定。
- 记忆要保守：默认不读，只在有帮助时读取，只写入用户明确支持的事实。
- 把修复作为一等能力：用户说“没理解”时，停止旧路径并重新连接。
- 危机行为保持简单：先稳定，再转向现实中的支持。
- 用回放用例做回归，而不是为每个坏例子增加关键词补丁。

## 最小 APP 循环

1. 接收用户消息。
2. 检查即时安全风险。
3. 选择回应模式：回答、陪伴、实用帮助、修复或稳定。
4. 只有必要时读取相关记忆。
5. 用统一的陪伴者声音生成一条可见回复。
6. 回复后可选地更新用户偏好、稳定背景或部分笔记。
7. 记录足够的结构化数据来评估失败。

## 第一版应避免

- 多个可见 agent 争抢发言。
- 除非产品确实需要可追踪性，否则不要设计大型 JSON 合同。
- 每条消息都进行深度记忆检索。
- 过重的临床标签或治疗协议。
- 针对单个失败样例编写运行时关键词补丁。

## 评测覆盖

至少覆盖：

- 信息很少的输入。
- 情绪表达。
- 实用建议请求。
- 内在冲突和部分语言。
- 用户指出“没理解”。
- 用户询问身份或能力边界。
- 危机或高风险输入。
- 不应读取记忆的场景。
- 用户要求记住稳定偏好的场景。
